# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is a **literate Emacs configuration** using Org Mode (`config.org`) that tangles to `config.el`. It replicates Doom Emacs ergonomics (Evil mode, SPC leader keys) using vanilla Emacs packages. The configuration is heavily optimized for Emacs 30+ with native compilation.

## Architecture

**Entry Point Chain:** `init.el` → bootstraps Elpaca → tangles `config.org` → loads `config.el`

**Key Files:**
- `config.org` — Main literate configuration (EDIT THIS). All Emacs Lisp lives inside `#+begin_src emacs-lisp` blocks.
- `config.el` — Auto-generated by tangling `config.org`. Do not edit directly.
- `init.el` — Minimal bootstrap that sets up Elpaca package manager and loads the tangled config.
- `early-init.el` — Startup optimizations (GC, native-comp settings, frame defaults).

**Package Management:** [Elpaca](https://github.com/progfolio/elpaca) (async package manager). Packages declared with `use-package` / `:elpaca` keyword in `config.org`.

**Generated Data Location:** `.local/` directory (Git-ignored). Contains installed packages (`elpaca/`), LSP data, caches, and state.

## Common Commands

**Package Management:**
```bash
./bin/emacs-cli sync        # Install packages and sync config
./bin/emacs-cli update      # Update all packages
./bin/emacs-cli doctor      # Health check
./bin/emacs-cli purge       # Clean builds/caches (fixes compilation errors)
```

**Validation:**
```bash
./bin/test-validators       # Full validation suite (blocks, parens, tangle, startup, byte-compile)
./bin/validate-config        # Validate config.org blocks and tangling
```

**For Elisp files:**
```bash
python3 bin/validate-lisp-syntax.py FILE.el
```

**Smoke Test:**
```bash
emacs -Q --batch --eval '(setq user-emacs-directory default-directory)' -l init.el --eval '(message "Startup OK")'
```

**Byte-Compile (Strict):**
```bash
emacs -Q --batch -L . --eval '(setq byte-compile-error-on-warn t)' -f batch-byte-compile init.el early-init.el
```

## Configuration Validation Rules

**Elisp files (`init.el`, `early-init.el`):**
- Validate with: `python3 bin/validate-lisp-syntax.py FILE.el`

**Org Configuration (`config.org`):**
- Validate with: `./bin/validate-config`
- All Lisp code MUST be inside `#+begin_src emacs-lisp ... #+end_src` blocks
- Block markers must be balanced (no missing/extra `end_src`)
- Quotes in strings: escape inner quotes with backslash (`\"`), not backticks
- Regex in strings: double-escape backslashes (`"^\\* User"`)

## Session Snapshot Workflow

At the start of each working session (first action after opening repo), create a rollback snapshot:

```bash
mkdir -p snapshots/$(date +%Y%m%d-%H%M%S)
cp -a init.el early-init.el config.org bin/ README.md snapshots/$(date +%Y%m%d-%H%M%S)/
```

Rollback by restoring from `snapshots/<timestamp>/` via `cp -a`.

## Key Bindings (Doom-style)

- `SPC` — Leader key (Normal/Visual states)
- `M-SPC` — Global leader (Insert/Emacs states)
- `SPC .` — Find file
- `SPC ,` — Switch buffer
- `SPC ;` — Embark Act
- `SPC u` — vundo (visual undo tree)
- `SPC g s` — Magit status
- `SPC c a` — Eglot code actions
- `SPC c f` — apheleia-format-buffer

## Important Notes

- `init.el` uses file-local variable (`-*- byte-compile-warnings: (not free-vars unresolved); -*-`) to suppress false-positive warnings from async Elpaca loading. Do not add `with-no-warnings` or `eval-when-compile` blocks to suppress these.
- Native compilation uses `native-comp-jit-compilation` (not the obsolete `comp-deferred-compilation`).
- Focus-out hooks use `after-focus-change-function` via `add-function` (not `focus-out-hook`).
- Always validate `config.org` before running full test suite.
- Custom functions are defined in `config.org` under the "Custom Functions" heading — verify their existence before using them in changes.
